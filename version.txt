Release Notes - first public release

Summary
LaunchBridge is a set of AI coding agent skills, plus a CLI installer, that gives an agent working on a codebase persistent context, guardrails and tooling: codebase and artifact Q&A, governance files, a config and prompt registry, tests, prediction runs and evaluation, data preparation, and cost and latency reporting. It runs on the developer's workstation under the developer's own AWS credentials and calls Amazon Bedrock in that account. It is sample code for proof-of-concept and non-production use.

Skills
- indexing-and-qa, code-guardrails, config-prompt-registry, testing-framework, data-wrangler, generate-predictions, evaluate-predictions, comparative-metric-analysis, operational-metrics, feature-recommendations, and lb-setup (setup and integrity checks)
- Optional AI skill bundles from aws-samples/sample-ai-skills (pinned at v0.6.2), one per domain: AI Spec-Driven Development (with the ai-workflow orchestrator), AI Architecture Decisions, AI Agent Context, AI Development Process, AI Prose Documents and AI Software Documentation; the release domain is not offered. On first use, the AI Prose Documents export skills fetch a Python 3.14 interpreter and pinned packages through uv, and ai-human-pdf fetches a pinned Mermaid renderer through npx when node is installed

Known Dependency Advisories (not yet fixed)
- Pillow 12.3.0 (41 advisories in Grype's database on 2026-10-29, all fixed only in Pillow 13.0.0): LaunchBridge's one frozen dependency set pins 12.3.0 because strands-agents-tools and streamlit, which IRIS (indexing-and-qa) requires, don't allow Pillow 13 yet; installs without indexing-and-qa get the same pin. Reachable: Pillow decodes images inside indexed project artifacts and in media evaluated by evaluate-predictions, where a crafted image can cause out-of-bounds reads or a denial of service. Don't index or evaluate untrusted files until it is updated.
- Pillow 12.3.0 in the optional ai-human-pdf skill: the lock file that ships with its upstream script pins the same Pillow, which decodes the cover logo a document or the --logo option names. Don't export documents that name an untrusted logo until upstream updates it.
- mcp 2.1.1: GHSA-84m7-p3x7-pcfv (CVE-2026-59951, stateful Streamable HTTP server sessions), GHSA-5h93-6whr-6q8j (HTTP and SSE client redirects), GHSA-w4fh-qvv9-3v23 (HTTP server bearer-token audience) and GHSA-rwrf-2pqf-9j8j (client $ref fetches in tool output schemas). Not reachable: every MCP server LaunchBridge registers runs over stdio, and the Q&A launcher refuses IRIS's mcp_servers, the only way it would act as an MCP client. The fixed versions (2.2.0, 1.30.0) can't be installed yet because IRIS and strands-agents require mcp<2.2.
- tornado 6.5.10, a dependency of IRIS: GHSA-r4j5-9xpp-3985 and GHSA-pcg2-g6cj-q92c (HTTP server denial of service) and GHSA-pw9p-v7r6-gx4p (open redirect in RedirectHandler, low). Not reachable: LaunchBridge starts no tornado server. Fixed in 6.6, which IRIS allows; it will be picked up at the next dependency update.

Upgrade Notes
- Requires Node.js 22.12 or later and Python 3.12 or later
- After updating, re-run the launchbridge installer in each project, then lb-setup in your agent: lb-setup builds .venv_lb only from dependency files the installer recorded on this machine, and rebuilds a .venv_lb it didn't record
- LaunchBridge deploys no infrastructure; explicitly invoked AWS and Bedrock workflows may incur charges
